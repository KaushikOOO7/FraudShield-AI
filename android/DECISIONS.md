## Backend questions and proposed contract changes

These are recorded requests, **not accepted API changes**. No guessed endpoint is called by the UI. Continue local previews until confirmed; Phase 2 must verify payloads against the teammate's OpenAPI/samples.

```text
CONTRACT-CHANGE: POST /api/v1/device/register | request body | no request schema provided | confirm {} or define required device fields; no advertising/device identifier
CONTRACT-CHANGE: POST /api/v1/analyze | payload | keys/size limits unspecified for five types | propose sms:{text,source?}, call:{phone}, url:{url}, qr:{text}, screenshot:{evidence_ref}; validate with teammate before live use
CONTRACT-CHANGE: GET /api/v1/history | items[] | item fields and date grouping unspecified | propose complete analyze result plus type and created_at; keep next_cursor nullable opaque string
CONTRACT-CHANGE: GET /api/v1/case/{id} | timeline[] | full-case timeline schema absent | propose [{agent,event,at}] with ISO8601 UTC at; preserve analyze result fields
CONTRACT-CHANGE: POST /api/v1/feedback | endpoint/body | “Mark as safe” requested but no API schema | propose {case_id,feedback:"mark_safe",note?} → {feedback_id,status}; feedback must not overwrite the backend verdict
CONTRACT-CHANGE: DELETE /api/v1/me | response and auth lifecycle | deletion requested but not part of supplied API section | propose 204 on confirmed deletion, invalidate token; wipe Room/preferences only with explicit user intent and show pending remote deletion when offline
CONTRACT-CHANGE: POST /api/v1/evidence | upload | screenshots/APK attachment upload not defined | propose multipart evidence file → {evidence_ref,expires_at}; size/MIME/retention rules required; never silently base64-upload a screenshot in /analyze
CONTRACT-CHANGE: GET/POST /api/v1/family/members | member_ids | contact numbers cannot be substituted for opaque IDs | propose opt-in member enrollment/list with {member_id,display_name,consent_status}; no family send until enrollment consent confirmed
CONTRACT-CHANGE: POST /api/v1/report | idempotency | safe offline retries need deduplication | propose Idempotency-Key request header with stable outbox UUID and server deduplication; same policy for analyze/family actions
CONTRACT-CHANGE: GET /api/v1/trends | threats_blocked and time ranges | v1 client only warns; daily/week/month blocked totals absent | define whether backend blocks threats elsewhere; expose threats_warned and date-window counts or replace UI “blocked” copy with accurate wording
CONTRACT-CHANGE: all endpoints | error.code | exact taxonomy missing | provide documented uppercase codes, retryability, rate-limit Retry-After, and session-expiry handling
```

Auth scheme, verdicts (`VERIFIED|SAFE|CAUTION|HIGH_RISK|CONFIRMED_FRAUD`), agent statuses (`OK|LOW|SUSPICIOUS|HIGH`), locales (`en|hi|kn`), cursor pagination and UTC timestamps remain fixed as supplied. Notification events map to `sms` because the contract has no `notification` type; source metadata and redaction still need confirmation. VERIFIED is attention-worthy by the supplied `verdict != SAFE` rule, but uses a calm positive tone rather than a high-importance fraud warning. Background warning eligibility will be explicit CAUTION/HIGH_RISK/CONFIRMED_FRAUD, not lexical enum ordering.

## Android and release follow-ups

`ROLE_CALL_SCREENING` request API starts at Android 10/API 29, although CallScreeningService exists earlier. Android 8/9 must remain in manual number-check mode unless an independently validated route is approved; no call-log fallback. Notification access is broad at the OS level, so Phase 2 must implement an explicit allowed-app selection before cloud submission, a consent gate, online check, ephemeral prefilter and 10-minute source/content debounce. The receiver/listener will use bounded lifecycles, cancellation and background work appropriate to Android 12+, not an unbounded service.

SMS Play distribution, POST_NOTIFICATIONS rationale, family/member consent, draft DPDP notice (data fiduciary/grievance contact/retention), encrypted cached evidence, token refresh, outbox idempotency, schema export, agent-name localization, translated error copy, accessibility on-device and release target requirements are not marked complete. APK upload/inspection is not enabled before a signed backend evidence-upload contract exists.
